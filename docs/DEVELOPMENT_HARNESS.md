# 개발·검토·검증 하네스

## 지속 목표

통합 채용공고 프로그램: 여러 출처를 같은 데이터 계약·검색 흐름으로 연결한다.
수집 성공이나 개별 실험 도구의 개수를 제품 완성으로 간주하지 않는다.
사용자 접근성: 명령어·JSON 지식 없이 공고를 열고 조건을 조정하고 원문으로 이동할 수 있어야 한다.

## 반복 절차

1. 구현 전: 사용자 흐름과 보호할 기존 동작, 검증 가능한 완료 조건을 적는다.
2. 작은 구현: 수집 → 검증 → 스냅샷 → 화면의 실제 연결을 만든다.
3. 검토: 목표 기여, 잘못된 추천/누락, 출처·신선도 표시, 키보드·좁은 화면·오류 안내를 확인한다.
4. 테스트: 고정 fixture/실패 주입, 기존 ALIO 회귀, Python→TS 왕복, 화면·필터 확인.
5. 보완: 발견한 실패를 회귀 사례로 남긴 뒤 수정하고 관련 테스트를 다시 실행한다.
6. 인수인계: 변경 이유·검증 명령·실제 결과·미검증 사항·다음 행동을 작업 기록에 적는다.

## 보호 조건

README 수정, 파일 삭제, 유료 서비스 활성화 금지.
2026-11-14 후속 지시: 필요한 경우 검증이 끝난 PR은 에이전트가 main에 병합할 수 있다.
현재 미완료 작업은 초안으로 보관하며, 병합 전 회귀·제품 목표·접근성 검증을 완료한다.
커밋/PR 제목은 `feat: 공고 검증과 미리보기 추가`처럼 짧고 누구나 이해할 수 있게 쓴다.
기존 공공기관 수집기와 사용자 미커밋 변경을 보존한다.
현재 후속 PR은 PR #18 브랜치를 base로 사용한다. base 병합 시 후속 PR의 기준을 재확인한다.
사용자가 사이트별 이용 조건 확인 제약을 철회했지만 이용 권한 검증 완료를 주장하지 않는다.

## 이번 완료 조건

- 30~50개 고유 공개 상세 요청, 성공/리다이렉트/차단/누락을 별도 집계.
- 추출 결과를 그대로 정답으로 복사하지 않는 원문 대조. 완성도와 정확도 구분.
- 실제 발견한 레이아웃/조건 오류를 재현하는 합성 테스트와 보완.
- 공통 스냅샷으로 출처가 다른 공고를 함께 볼 수 있는 미리보기, 출처 필터.
- 원문 유지, 미상 조건을 확정 정보로 표시하지 않기, 최초 화면에서 모든 수집 공고 확인 가능.
- 간단한 실행 진입점, 검색/지역/경력 필터, 원본 이동, 키보드·모바일 확인.
- 운영 ALIO 기본 CLI/스케줄/데이터 유지. 미리보기 데이터 실패를 샘플로 숨기지 않기.

## 환경·재현 정보

프론트 통합 완료 기준은 기존 공고 화면에서 두 출처가 함께 표시되고, 검색·출처 필터·
상세·스크랩이 연결되는 것이다. 디버깅 화면은 추출 검증에 사용한다. 겹치는 테스트를 추가하지
않고 사용자 흐름을 한 번의 통합 테스트로 확인한다. 실제 공공기관 데이터와 가상 검증 데이터는
결과에 구분해 기록한다.

- Windows PowerShell, Node 24, Python 3.13 가상환경 `.venv-scrapling`.
- pnpm 11 sandbox symlink 오류 시 기존 설치된 `.bin` 도구 직접 실행.
- 기존 parser CLI 테스트는 Windows URL.pathname 문제 3건. Linux Node 22/24 CI로 전체 확인.
- Git CLI push 인증 만료: GitHub 연결 도구로 tree/commit/branch를 게시하고 동일 tree hash 확인.
- 실제 관측/참고 HTML은 git 제외 `.scrapling-local/`에만 저장. 합성 회귀 fixture와 집계만 커밋.
- `docs/VALIDATION_PREVIEW_LOG.md`에 이번 반복 기록을 유지한다.
